## Decisions (agreed changes to SPEC.md)
<!-- e.g. "D1.3: LangChain Gemini embeddings do not support output_dimensionality, using a google-genai wrapper" -->
- D1.1: Python 3.14 (system version) instead of 3.12 as CLAUDE.md/SPEC say; `requires-python = ">=3.12"`, `.python-version` = 3.14, Dockerfile uses python:3.14-slim. All dependencies resolved.
- D1.1: /api/health returns HTTP 200 with `{"status":"degraded","db":false}` when the DB is down (keeps Render's health check alive).
- D1.1: psycopg 3 async cannot use Windows' default ProactorEventLoop, so Alembic and later CLI commands use `app.loop.run()` (SelectorEventLoop). `uvicorn --reload` already uses the selector loop; without `--reload` on Windows use `--loop app.loop:selector_loop_factory`.
- D1.1: Docker db is published on host port 5433 (not 5432) because a native Windows Postgres uses 5432. docker-compose.yml, .env.example and the config.py default use `localhost:5433`; inside Docker and in CI the port is still 5432.
- D1.1: an empty `DATABASE_URL=` in .env falls back to the local default.

- D1.2: tests use a real Postgres database `answerwatch_test` on the same server as `DATABASE_URL` (override with `TEST_DATABASE_URL`), created and dropped by a fixture; Kemira data is never touched. CI uses the Postgres+pgvector service container the same way.
- D1.2: re-import updates company fields, competitors and knowledge sources; questions are only created, never changed. Nothing is deleted. New column `active boolean default true` on `competitors` and `knowledge_sources`: items missing from the YAML get `active=false` and are ignored by the agents (mention matching, onboarding); if they return to the YAML they become `active=true` again.
- D1.2: all project files are written as UTF-8 without BOM (rule added to CLAUDE.md under "While working"); PROGRESS.md was converted from Windows-1252.
- D1.2: unknown keys in a profile YAML are validation errors (typo protection); `tolerance` and `unit` are only allowed together with `expected_value`.
